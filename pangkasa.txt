Setelah loop selesai (finally block):
Di sini ada yang jelas bisa dipangkas tanpa mengurangi listening time sama sekali — lihat baris 2183-2193: finally:
    try:
        with serial.Serial(PORT, baudrate=baud, timeout=0.05) as ser:  # ← BUKA KONEKSI BARU
            send_command(ser, stop_cmd)
    except Exception:
        pass Padahal koneksi serial yang sama (ser) baru saja dipakai persis di atasnya untuk loop scanning, lalu ditutup otomatis waktu with block di try selesai (loop break) — habis itu dibuka lagi dari nol cuma buat kirim stop command. Menutup+membuka ulang port serial di Raspberry Pi biasanya makan waktu jauh lebih lama dari sekadar time.sleep() (re-init device node, kadang 100-500ms+), padahal ini murni overhead protokol, bukan bagian dari "dengar tag".
Perbaikan konkret — kirim stop_cmd pakai koneksi yang sama, sebelum with di try block ditutup: try:
    with serial.Serial(PORT, baudrate=baud, timeout=0.05) as ser:
        # ... setup commands ...
        while True:
            # ... loop scan ...
        send_command(ser, stop_cmd)   # <-- kirim di sini, pakai ser yang sudah terbuka
except Exception as e:
    log.error("[SCAN] Async scan error: %s", e)
finally:
    GPIO.output(SHUTDOWN_GPIO, GPIO.HIGH)
    log.info("[SCAN] Async scan stopped") Ini menghilangkan satu siklus close+reopen port secara gratis, tanpa menyentuh MAX_SCAN_TIME/reduction sama sekali.

RFMODE (0.5s) + SESSION (0.3s) + TARGET (0.15s) + Q (0.15s) = 1.1s hanya dipakai di jalur AA48. Kalau pindah ke inventory_mode: "AA58", keempatnya di-skip otomatis (lihat komentar baris 2023-2032) — tapi ini ganti algoritma inventory-nya, bukan cuma pangkas delay, jadi perlu tes ulang stabilitas tag.
Delay send_command_checked (0.15-0.3s per command, ada ~9 command) itu margin aman untuk tunggu respons serial di 921600 baud — secara teori respons ACK sependek itu harusnya jauh di bawah 150ms, jadi mungkin bisa dikecilkan (misal ke 0.08-0.1s), tapi ini beresiko kalau modul kadang lambat merespons → command jadi keliatan "NO RESPONSE" padahal cuma telat.
time.sleep(1.0), time.sleep(0.5) di scan_worker(), dan time.sleep(1) di set_baudrate() — ini jeda settle hardware setelah power-up/ubah baud. Paling beresiko dipangkas karena bisa bikin modul belum siap → gagal konek.
